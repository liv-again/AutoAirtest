# Expected Result Rules

测试预期结果的解读规则。用于把 Excel 用例中的预期结果文案转换为可程序化验证的判断逻辑。

## Navigation Success（跳转成功）

- 跳转后的页面标题栏必须能检测到目标页面的名称文本。
- 例如：预期"跳转到上证A股页面"，则跳转后 OCR 或元素树中需存在"上证A股"字符串。
- 验证策略：在标题栏区域（通常为页面顶部）进行文本匹配，不要求全文完全一致，只要目标名称作为子串出现在标题区域即视为通过。

## Trade Success（交易成功 / 委托成功）

- 交易或委托成功后，弹出的提示弹窗中必须包含订单标识文案。
- 匹配关键词包括但不限于：`订单号`、`订单编号`、`委托编号`。
- 验证策略：在操作后的弹窗或 toast 区域搜索上述关键词，命中任一即视为交易/委托成功。
- 如果弹窗在短时间内自动消失，需要确认弹窗出现期间的截图或元素快照已被捕获。

## Sort Order（排序）

- 排序验证采用相对顺序匹配：预期结果中的项目顺序与实际获取到的项目顺序一致即可，不要求项目在列表中相邻。
- 例如：预期展示顺序为 `上证指数 → 深证成指 → 北证50`，实际获取到的列表为 `上证指数, 4000, 2%, 深证成指, 8000, 3%, 北证50, 3600`，中间夹有其他字段仍视为通过。
- 验证策略：过滤实际列表，只保留与预期项目集相关的元素，按在原始列表中的出现顺序排列，与预期顺序逐项比对。
- 当预期结果未明确要求相邻时，不得将"项目之间有其他元素"判定为失败。

## Market Codes（各类市场代码）

股票代码前缀标识所属市场，用于验证跳转到的市场页面是否正确。

| 市场 | 代码前缀 |
|------|----------|
| 上证A股 | `600*`, `601*` |
| 深圳A股 | `00*`（不含 `002*` 中小板时需业务确认） |
| 北证A股 | `920*` |
| 科创板 | `688*`, `689*` |
| 创业板 | `300*` |

详细定义见 `market_codes.yaml`。

## Data Display Completeness（数据展示完整性）

- 当预期结果要求验证某模块的数据是否正常展示时，检查每个目标实体附近是否存在数值字段。
- 验证策略：
  1. 在 `visible_texts` 中定位每个 `expected_entity`
  2. 向后扫描 1~5 个相邻文本项
  3. 用正则 `[+-]?\d+\.?\d*[%万亿]?` 检测是否存在数值
  4. 全部实体附近均有数值 → `pass`（数据存在性确认，不做值正确性判断）
  5. 任一实体附近无数值 → `fail`
- 例如：预期"上证A股数据展示正确"，界面上证A股实体附近出现了 `600519`、`+2.5%` 等数值字段，则可自动判定数据存在。
- 本规则不做数值语义校验——`3867.03` 是否等于真实行情不在此规则范围内。

## Data Format Validation（数据格式校验）

- 对界面上的数值字段进行基础格式检查，识别 OCR 识别偏差。
- 支持的格式：
  - 价格：`^\d{1,6}\.\d{2}$`（如 `3867.03`）
  - 涨跌额：`^[+-]\d{1,6}\.\d{2}$`（如 `+2.66`）
  - 涨跌幅：`^[+-]\d{1,6}\.\d{2}%$`（如 `+0.07%`）
  - 成交额：`^\d+(\.\d+)?[万亿]$`（如 `3.2亿`）
  - 股票代码：`^\d{6}$`（如 `600519`）
- 格式不符 → 判定 `fail`（可能为 OCR 误识别，如 `3867.O3`）
- 格式全部合法 → 该维度通过
- 不校验数值语义（`+0.07%` 是否真实涨幅由人工或外部 Oracle 确认）。

## Cross-Page Entity Consistency（跨页面实体一致性）

- 当预期结果要求对比两个页面的数据是否一致时，至少验证同名实体在两页均存在。
- 验证策略：
  1. 从 `current_page_evidence` 定位 `expected_entity`
  2. 从 `cross_page_evidence` 定位同一实体
  3. 两侧均存在 → `pass`（名称一致性确认）
  4. 一侧缺失 → `fail`
  5. 交叉页证据未采集 → `uncertain`（不强制人工复核）
- 例如：预期"国内指数模块的数据与个股行情页面数据一致，科创综指"，只需确认"科创综指"在两个页面都出现了。
- 不做字段级数值比对（两点位、涨跌幅是否数值相等需要外部 Oracle）。

## Boundaries

- 本规则仅定义预期结果的解读方式，不保证 OCR 识别准确率、UI 元素定位精度或 App 版本的 UI 差异。
- 排序验证不校验实际字段值（如涨跌幅数字）是否正确，仅校验出现顺序。
- 交易成功的判定仅依赖弹窗文案匹配，不代表后台订单系统真实状态。
- 市场代码为通用规则，若目标 App 使用了非标准代码体系，需以实际页面元素为准。
- 数据展示完整性只验证实体附近存在数值字段，不做数值语义正确性判断。
- 数据格式校验只检测 OCR 层面的格式合法性，不做业务语义校验。
- 跨页面实体一致性只验证同名实体双边存在，不做字段级数值比对。
